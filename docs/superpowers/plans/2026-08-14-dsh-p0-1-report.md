## 二、prefix-cache 实测（T5）

- **实测**：第 1 次（冷缓存）`hit=0 miss=162 total=162 hit_rate=0.0%`；第 2 次（暖缓存）`hit=128 miss=34 total=162 hit_rate=79.0%`。两次运行稳定（暖缓存后第 1/2 次均为 79.0%）。API **返回** `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 字段 → cache **可观测**。
- **结论**：⚠️ 可观测，但「99% 命中」假设不成立（实测稳定 79%，非 99%）。根因：DeepSeek 以 64-token 块为缓存粒度，尾块 34 tokens 恒 miss（162 = 2×64 + 34）。
- **对 I7 成本模型的影响**：生产监控仍直接以 `prompt_cache_hit_tokens` 为指标（字段可观测），但成本模型须把「99% 命中」下修到块对齐上限 `⌊prompt_tokens/64⌋×64 / prompt_tokens`（本测 79%）。**须以「在真实 persona 前缀上重测后定稿上限」的措辞写入**（T5 审查建议）。
