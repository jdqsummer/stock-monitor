# 股票WEB监控系统 — 需求与设计方案（主计划）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement sub-plans task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标:** 开发一款基于 AI 企业价值与安全边际分析的股票监控 Web 系统，支持持仓/自选股实时监控、AI Agent 投资分析（分析 Agent + 数据采集 Agent）、LangGraph 编排 + OpenHarness 投资框架约束。

**架构:** 前后端分离，Python 后端（FastAPI + LangGraph + OpenHarness），React 前端，SQLite/PostgreSQL 持久化，Redis 缓存，westock-mcp 数据源，支持多 LLM（千问/DeepSeek/GLM/Kimi）。

**技术栈:** Python 3.11+, TypeScript 5.x, FastAPI, React 18, LangGraph, OpenHarness, SQLite → PostgreSQL, Redis, Docker, westock-mcp

## 全局约束

- 云端 Linux 部署，Web 访问，Docker 容器化
- 数据更新频率可配置（默认：早上/下午收盘各一次全量分析）
- 安全边际实时监控刷新间隔可配置（默认 30min）
- 支持多 LLM 模型切换与参数配置
- 所有分析基于内置价值投资分析框架（`投资分析框架.md`）
- 提供页面级配置面板（更新频率、个人信息、LLM 选择）
- 单一标的持仓上限 10%（框架纪律，非系统强制）

## 一、需求完善

#### F-4 数据采集 Agent
- 负责调用 westock-mcp 接口获取行情、财报、新闻、技术指标等数据
- 支持定时任务调度（默认：交易时段每 5min，非交易时段按需）
- 支持缓存（Redis）和数据更新频率配置（默认：早 9:30 + 下午 15:30 各一次全量分析）
- 支持数据质量校验（利润扣非口径、年化估算、PE 区间对照等）
- 支持数据回写到记忆系统（L1/L2/L3）

#### F-5 投资分析 Agent（分析 Agent）

分两种情况：
1. 用户主动发起分析：输入企业名称或股票代码，Agent 调用 westock-mcp 获取数据，执行 9 步分析链，输出结构化分析报告。（对话方式）

**F-5.1 分析流程**
```
后台自动分析每只自选股
  → 工具调用（westock-mcp：行情/财报/新闻/技术指标）
  → Harness 约束下执行投资分析框架（9 步分析链）
  → 输出结构化分析报告
  → 记忆回写（关注的股票 → L1）
```

**F-5.2 分析报告输出内容**
- 逆向清单结论（14 问摘要）
- 量化评级表（按 `投资分析框架.md` 第八章格式）
- 三大校验锚点对照
- 行动纲领（买入/观察/放弃 + 理由 + 风险提示）

**F-5.3 Harness 约束**
- 必须经过 9 步分析链，不得跳过
- 利润必须用扣非口径（原则一）
- 年化必须保守估算（原则二）
- 必须执行逆向清单 14 问（原则五）
- 必须与投资清单对照（第六节）
- 输出只保留结论不保留推理过程（原则八）

2. 系统定时分析：默认每天早 9:30 + 下午 15:30，Agent 自动分析所有自选股，更新所有自选股的数据。也可以手动触发，触发后，有一个小小的转圈圈提示用户真正后台分析。


#### F-6 LLM 与数据源配置

**F-6.1 LLM 配置**
- 支持的模型列表：千问（qwen-max/qwen-plus）、DeepSeek（deepseek-chat）、GLM（glm-4）、Kimi（moonshot-v1）
- 模型参数可配置：temperature、max_tokens、top_p
- API Key 管理（加密存储）

**F-6.2 数据源配置**
- westock-mcp 连接配置（API 凭证）
- 行情数据更新频率（默认：交易时段 5min，非交易时段按需）
- 分析更新频率（默认：早 9:30 + 下午 15:30 各一次全量分析）

#### F-7 系统配置页面

- 个人信息（投资风格偏好、风险承受度 → 影响 L3 画像初始化）
- 数据更新频率设置
- LLM 模型选择与参数
- westock-mcp 凭证管理

### 3.3 数据模型设计（核心表）

```sql
-- 用户表
CREATE TABLE users (
    id          TEXT PRIMARY KEY,
    username    TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    config      JSON,          -- 用户配置（LLM选择、刷新频率等）
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 自选股
CREATE TABLE watchlist (
    id          TEXT PRIMARY KEY,
    user_id     TEXT REFERENCES users(id),
    stock_code  TEXT NOT NULL,          -- 股票代码
    stock_name  TEXT NOT NULL,          -- 股票名称
    industry    TEXT,                   -- 行业分类
    added_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    notes       TEXT,                   -- 用户备注
    UNIQUE(user_id, stock_code)
);

-- 持仓记录
CREATE TABLE positions (
    id              TEXT PRIMARY KEY,
    user_id         TEXT REFERENCES users(id),
    stock_code      TEXT NOT NULL,
    stock_name      TEXT NOT NULL,
    shares          REAL NOT NULL,       -- 持有数量
    cost_price      REAL NOT NULL,       -- 成本价
    purchased_at    TIMESTAMP,          -- 买入日期
    UNIQUE(user_id, stock_code)
);

-- 安全边际分析快照
CREATE TABLE analysis_snapshots (
    id              TEXT PRIMARY KEY,
    user_id         TEXT REFERENCES users(id),
    stock_code      TEXT NOT NULL,
    annual_profit   TEXT,               -- 年化净利（区间）
    profit_method   TEXT,               -- 计算方法 H1×2 / Q1×4
    swing_pe        TEXT,               -- 击球区 PE
    swing_market_cap TEXT,              -- 击球区市值
    swing_price     TEXT,               -- 对应股价
    current_market_cap REAL,            -- 当前市值
    current_price   REAL,               -- 当前股价
    distance_pct    REAL,               -- 距击球区%
    rating          TEXT,               -- 🟢/🟡/🔴
    data_date       DATE,               -- 数据日期
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, stock_code, data_date)
);

-- 对话记录（L0 层）
CREATE TABLE conversations (
    id              TEXT PRIMARY KEY,
    user_id         TEXT REFERENCES users(id),
    agent_type      TEXT NOT NULL,       -- analysis/data_collection
    messages        JSON NOT NULL,       -- [{role, content, timestamp}]
    summary         TEXT,               -- 对话摘要
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 记忆条目（L1/L2 层）
CREATE TABLE memories (
    id              TEXT PRIMARY KEY,
    user_id         TEXT REFERENCES users(id),
    level           TEXT NOT NULL,       -- L1/L2/L3
    category        TEXT,               -- 分类（偏好/策略/画像等）
    content         TEXT NOT NULL,       -- 记忆内容
    source          TEXT,               -- 来源（conversation_id / analysis_id）
    confidence      REAL DEFAULT 1.0,   -- 置信度
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 行业分类表
CREATE TABLE industries (
    id              TEXT PRIMARY KEY,
    name            TEXT NOT NULL UNIQUE,
    parent_id       TEXT REFERENCES industries(id),
    typical_pe_range TEXT               -- 典型 PE 区间（用于分析参考）
);
```

### 3.4 记忆层级架构（L0-L3）

| 层级 | 名称 | 存储 | 内容 | 生命周期 |
|------|------|------|------|----------|
| L0 | 对话记录 | `conversations` 表 | 原始对话全文 | 永久保留 |
| L1 | 投资偏好 | `memories` (L1) | 用户关注的股票、行业偏好、事实信息 | 异步蒸馏，持续更新 |
| L2 | 场景知识 | `memories` (L2) | 投资策略模式、行业认知、分析框架调整 | 定期更新 |
| L3 | 投资画像 | `memories` (L3) | 风险偏好、行为模式、决策风格、认知偏差 | 周/月更新 |

### 3.5 API 设计（核心端点）

```
# 仪表盘

# 股票详情

GET    /api/stocks/{code}/kline          # K线数据

# 分析 Agent
```

### 3.7 安全边际信号灯计算逻辑

```python
def calculate_signal(distance_pct: float) -> dict:
    """
    计算安全边际信号灯。

    输入：距击球区百分比（当前股价相对击球区上限的偏离）
    规则（基于 投资分析框架.md 第六章）：
      - distance_pct <= 0  → 🟢 绿灯（已在击球区内/可配置买入区间）
      - 0 < distance_pct <= 30% → 🟡 黄灯（接近击球区/观察列表）
      - distance_pct > 30% → 🔴 红灯（远离击球区/暂不配置）
      - 亏损企业 → 🔴
    """
    if distance_pct <= 0:
        return {"signal": "green", "label": "击球区", "action": "可配置/买入"}
    elif distance_pct <= 0.30:
        return {"signal": "yellow", "label": "观察区", "action": "等待时机"}
    else:
        return {"signal": "red", "label": "高估区", "action": "暂不配置"}
```

## 五、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| westock-mcp 不稳定/接口变更 | 数据不可用 | 抽象数据层接口，缓存降级，支持手动数据输入 |

| 实时监控刷新频率 vs API 限流 | 刷新不及时 | 可配置刷新间隔，缓存策略，非交易时段降频 |

## 六、术语表

| 术语 | 定义 |
|------|------|
| 击球区 | 年化净利 × 行业合理 PE 区间，即价值投资者愿意买入的市值范围 |
| 距击球区 | (当前股价 − 击球区上限股价) ÷ 击球区上限股价，量化安全边际的指标 |
