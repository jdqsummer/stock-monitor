# Stock Monitor 技术白皮书

AI 驱动的 A 股安全边际分析平台。核心理念：**好价格下的好公司**。

| | |
|:--|:--|
| 文档版本 | v1.0（2026-08-26） |
| 代码规模 | 后端 81 个 Python 模块 / 前端 React 19 + TypeScript / 测试 580 例 |
| 部署形态 | Docker Compose 五容器（app / frontend / nginx / redis / dsh-engine） |

## 1. 项目定位

Stock Monitor 是一套面向个人价值投资者的**决策辅助系统**，而非行情交易工具。它将一套成文的价值投资方法论（《投资分析框架》，8 项硬约束原则）工程化为可重复执行的 AI 分析流水线：

- 输入：任意 A 股 / 港股代码（公开 HTTP 行情与财报数据自动采集）。
- 输出：五段式结构化分析报告（定性 → 行业 PE 锚定 → 击球区 → 逆向清单 → 结论），以及三色信号灯（🟢 击球区 / 🟡 观察区 / 🔴 高估区）。
- 主张：**输出结论，不输出过程**；LLM 只做定性判断，一切确定性计算由纯函数完成。

系统的三个支柱：

1. **DSH 五段分析引擎**（DeepSeek DSH Harness）：LLM 定性分析主路径。
2. **确定性计算双实现收敛**：TS 纯函数（dsh-engine `/calc`）为主、本地 Python 节点兜底。
3. **永不阻断的优雅降级**：任何外部依赖（数据源 / Redis / DSH / LLM / SMTP）不可用时自动降级，系统持续可用。

## 3. 投资方法论与领域模型

### 3.1 八项原则（硬约束，不可修改）

1. 利润质量优先（扣非净利润口径）
2. 保守年化（H1×2 优先）
3. 行业 PE 锚定
4. 多元估值校验
5. 证伪优先（逆向清单）
6. 好公司 ≠ 好投资（价格决定买不买）
7. 评级可修正
8. 输出结论不输出过程

### 3.2 五段式分析

| 段 | stage 键 | 性质 | 内容 |
|:--|:--|:--|:---|
| ① | `analyze_qualitative` | LLM 定性 | 商业模式 / 护城河 / 经营质量三维度 |
| ② | `anchor_industry_pe` | 确定性+LLM | 年化利润区间 × 行业 PE 区间 → 击球区市值/股价 |
| ③ | `swing_zone`（并入②输出） | 确定性 | 击球区量化 + 距击球区% + 三色信号 |
| ④ | `run_reverse_checklist` | LLM 定性 | 14 道逆向反问清单（公司/估值/共识/自己四组） |
| ⑤ | `output_conclusion` | LLM 定性 | 先结论后建议；评级可含否决 |

持仓股走 **position 模式**：③⑤替换为 `sell_analysis`（4 卖出原则 + 2 规避陷阱）与 `sell_conclusion`，并计算卖出区。

### 3.3 信号灯规则（不可修改）

自选安全边际信号——`距击球区 = (现价 − 击球区上限价) ÷ 击球区上限价`：

- ≤ 0% → 🟢 击球区（可配置/买入区间）
- 0 ~ 50% → 🟡 观察区
- \> 50% → 🔴 高估区（坚决放弃/太难）
- 年化利润下限 < 0 → ⚪ 无法量化（先验证商业模式与盈利拐点）
- 利润质量警示时 🟢 强制下调为 🟡

持仓卖出信号——`距卖出区 = (现价 − 卖出价) ÷ 卖出价`：

- ≥ 0% → 🔴 建议卖出；-20% ~ 0% → 🟡 接近；≤ -20% → 🟢 持有
- 亏损或卖出价无效 → 无信号

### 3.4 否决链

`unassessable_risk`（重大风险使安全边际无法评估）或 `checklist_veto`（14 道清单出现否决项）→ 后端 `apply_veto` 强制覆盖评级为 🔴「坚决放弃-太难」。设计要点：**只覆盖结论字段，不改价格信号**——UI 同时呈现"便宜"与"不可买"。DSH 侧 invest-guard 的 veto 属业务结论而非工具错误，不作阻断作废五段，最终否决由后端兜底。

### 4.3 数据模型（SQLAlchemy 2.0 async）

**A 表（跨用户共享的事实数据）**

- `stock_snapshots`：每股票一行行情快照（价格/市值/PE/总股本）。
- `financials`：每 `(code, report_period)` 一行财报（营收/归母/扣非/ROE，唯一约束）。

**B 表（每用户衍生数据）**

- `analysis_snapshots`：每 `(user_id, stock_code)` 一行 upsert。关键设计：**watchlist 组与 sell 组字段并存互不覆盖**——position 保存只写 sell 组、watchlist 保存只写 watchlist 组；`stage_results` / `stage_results_sell` 分别存两种模式的五段 JSON；`analysis_mode` 仅记录最近一次模式。前端按 `stage_results` 是否含 `anchor_industry_pe` 判定视图，不依赖单值 mode。
- `watchlist` / `portfolios` / `reminders`：自选、持仓、提醒。
- `users` / `conversations` / `memories`：认证、聊天会话（单一真相源）、记忆条目。
- `diaries` / `diary_folders`：笔记正文 + 自引用 parent_id 任意嵌套文件夹。

## 5. 核心技术设计

### 5.1 DSH 五段分析链路

**部署拓扑**：「容器内 SDK 宿主 + HTTP 触发」。backend 不持 SDK，经 `HttpDshRunner` POST `http://dsh-engine:8001/trigger`。

一次分析的完整旅程：

1. **触发**：`POST /trigger`，payload 含 code/name/context/model/session_id/pe_override/ralph_enabled/api_keys。超时设 1800s（五个 agent() 串行实测 ~10min）。
2. **上下文注入**：`build_context()` 从 AnalysisState 只挑确定性字段（quote / 近 8 期 financials / 近 10 条 news / 市值股本等）构建只读 context，原始 JSON 不进上下文（节约 token）。
3. **宿主执行**：sdk_host 包 DeepSeekHarness 跑一轮会话，提示模型调用 `invest-five-stage` 工具；工具内部串行执行 ①→⑤ 五个 agent()，各自挂载对应 `.dsh/skills/*` 方法论 skill 与插件。
4. **事件提取**：从会话事件流提取五段结构化结果（tool result）、真实路由模型、token 用量。
5. **映射回填**：`map_dsh_result_to_state()` 展平为 AnalysisState 字段并标记 `analysis_source=dsh-llm`。
6. **预算守卫**（I7）：单次 >100k token 或日累计 >1M → 附警告不阻断。
7. **落库渲染**：五段 JSON 存 `analysis_snapshots.stage_results[_sell]`，前端页内渲染。

**可靠性机制**：

- **会话唯一化**：session_id = `{code}-{date}-{uuid8}`。曾用 code-date 复用导致 harness 恢复空会话、turn 秒结束、五段提取失败（生产实测 2026-08-17 根因），唯一化根治。
- **S6 熔断**：连续失败 ≥3 次 → 开启 300s 冷却短路，期间全部直接走规则链；冷却结束恢复探测。
- **降级语义**：DshOrchestrator 只标记 `analysis_degraded`，降级链由调用方执行；`DSH_ENABLED=false` 时即便配置了 LLM 也走纯规则（LLM 定性强依赖 DSH）。
- **D6 重跑范围**：无快照 → full；快照 data_date=今天 → read_db；过期 → recompute45（仅重跑④⑤）。
- **D2 敏感性退路**：`run_sensitivity()` 以 PE±10% 重跑④⑤合并敏感性场景（默认不启用，能力预留）。

### 5.2 确定性计算双实现收敛（I4）

同一套计算存在 TS / Python 双实现，**收敛策略为主调 TS、失败回退 Python**：

- TS 权威实现：`.dsh/plugins/invest-calc/*.ts` —— `annualize` / `swingZone` / `safetyMargin` / `profitQuality` / `growthMetrics` / `peAnchor` 纯函数，由 calc_host 暴露 `:8002/calc`。
- 本地兜底：workflow.py 的 Python 同逻辑节点（硬约束 5：任何外部依赖不可用时不阻断）。
- 输入形状逐字对齐 TS interface（`_calc_input()` 负责转换）。
- 注意：`.dsh/plugins/invest-*/index.mjs` bundle 是手工维护产物，不能 rolldown 重建，须按 P3 文档手工同步单行。

核心公式（margin_engine.py 与 safetyMargin.ts 一致）：

```text
击球区市值 = 年化净利润区间 × 行业合理 PE 区间
击球区股价 = 击球区市值 ÷ 总股本
距击球区   = (现价 − 击球区上限价) ÷ 击球区上限价
```

### 5.3 多渠道数据源 provider 链

`WestockClient` 门面按 `DATA_PROVIDER_PRIORITY`（如 `tencent,eastmoney,mock`）依次尝试，单源失败告警切下一源，全败回抛（上层跳过不阻断）。设计细节：

- TencentProvider：qt.gtimg.cn 行情 + smartbox 搜索；港股 `.HK` 直接解析（解除降级）。
- EastMoneyProvider：push2 行情 + searchapi 搜索 + F10 财报/行业。
- **财报诚实原则**：仅当链为纯 mock 时才允许 MockProvider 伪造财报；配了真实源则跳过 mock，真源无数据的股票诚实返回"无数据"，绝不把伪造财报当生产事实。
- 缓存：Redis 缓存代理，Redis 不可用时优雅跳过回退工厂函数。

### 5.4 Chat Agent Loop（方案 C）

backend 直调 LLM function calling 编排，SSE 推流（`chat_agent_loop.py`）：

1. `llm.chat(messages, tools)` 非流式解析 tool_calls；
2. 有调用 → 执行 backend 工具（`get_stock_snapshot` / `get_financials` / `search_stock` / `get_industry_pe` / `run_five_stage`）→ 回填 tool 消息 → 继续下一轮（max 5 轮）；
3. 无调用 → `chat_stream` 流式输出文本 chunk；
4. 会话存 `conversations` 表（单一真相源），每轮异步蒸馏 L1/L2（失败非致命）。

两个值得注意的工程点：

- **记忆注入**：检索顺序 L3 画像 → L2 策略 → L1 事实，注入 system prompt；persona 从 `.dsh/skills/invest-chat/SKILL.md` 热加载（改文件重启生效）。
- **伪工具调用过滤**：DeepSeek 偶发把 function calling 当正文输出 `<tool_calls>/<invoke>` XML（含全角竖线变体，且被流式拆成微块跨 chunk 分片）。`_ToolCallXmlStripper` 有状态过滤器按 opener 类型匹配闭合丢弃泄漏段，尾部未闭合标记前缀缓冲到下一 chunk。
- **@ 引用笔记**：聊天输入 @ 触发笔记/文件夹路径下拉，选中项 note_refs 随消息发送，后端聚合全文注入上下文——替代已删除的日记内置 AI 分析。

### 5.5 L0-L3 记忆系统

| 层 | 内容 | 生成方式 |
|:--|:--|:---|
| L0 | 对话原文（conversations 表） | 自动落库 |
| L1 | 事实性偏好（关注行业/股票、风险偏好、个人约束） | LLM 逐条提取，upsert 去重 |
| L2 | 策略模式（选股模式/交易习惯/决策风格/行为偏差） | 对话结束蒸馏 |
| L3 | 投资画像（风格标签/风险承受度/行业 Top3/认知偏差警示） | 整合 L1+L2 定期生成 |

蒸馏管道 `DistillationPipeline` 用三段 prompt 模板驱动；检索 `retrieval.py` 按 L3→L2→L1 注入聊天上下文。

### 5.6 定时任务体系

APScheduler 单例（`TaskScheduler`）：

- 全局：30min 财报刷新；16:00 收盘任务（B 表重算 + 击球区扫描生成未读提醒）。
- 每用户：行情刷新 job 与自动分析 job，按用户配置动态 sync（保存配置即 reconcile，启动时对齐）。

### 5.7 认证与多用户隔离

JWT HS256（24h 有效期）+ bcrypt；注册/登录双通道（密码 or 邮箱验证码，60s 限频、5min 过期）；密码重置同链路。开发期 SMTP 未配置时验证码降级控制台打印。所有业务表以 `user_id` 外键隔离；A 表行情/财报全局共享。

### 7.1 任意股异步分析

```
前端 Analysis 页搜索 → POST /api/analysis/run {code, mode}
  → analysis_job_svc 创建 job（source 作用域隔离，防自选/持仓并发冲突）
  → data_agent 并行采集 quote/financials/news/industry（provider 链）
  → snapshot_svc 写 A 表
  → DshOrchestrator.analyze() → POST dsh-engine /trigger（1800s 超时）
      成功 → map_dsh_result_to_state（source=dsh-llm）
      失败/熔断 → 规则子链（LangGraph 7 节点复用，degraded=true）
  → apply_veto 否决覆盖 → save_snapshot 写 B 表（按模式隔离字段组）
前端 GET /run/status 轮询 → 完成后页内渲染五段
```

### 7.2 收盘闭环（16:00）

```
APScheduler run_closing_tasks
  → run_recompute_analysis：全量自选/持仓 B 表重算（新行情 → 重算击球区/卖出区）
  → run_reminder_checks：扫描 green 信号 → 生成未读提醒
前端 useUnreadMessages 轮询角标 → 用户查看/标记已读
```

## 8. 部署架构

docker-compose 五容器：

| 服务 | 说明 |
|:--|:---|
| app | FastAPI。启动命令先 `alembic upgrade head` 再 uvicorn；网络别名 `backend`（DSH invest-data-mcp 连 `http://backend:8000/mcp/investdata`，service 名却是 app，缺别名 MCP 通道建立失败）；挂 `app_data` 卷持久化 SQLite 与日记图片 |
| frontend | Node 构建产物拷入 `frontend_dist` 共享卷后退出 |
| nginx | 80 端口静态资源 try_files SPA；`/api/` 反代（变量 upstream + Docker DNS resolver，容器重建 IP 变化自动重解析避免 502）；`/api/chat/stream` 精确匹配关闭 buffering、read_timeout 300s |
| redis | 缓存（不可用时优雅降级） |
| dsh-engine | node:22 基座（runtime wheel 需 glibc≥2.28，不用 alpine）；pnpm frozen-lockfile；Python venv 装 requirements + deepseek-harness-sdk==0.1.0rc6；entrypoint 起 calc_host（nohup 后台）+ 会话清理循环 + exec sdk_host；`.dsh/skills`、`.dsh/plugins` 只读挂载（I3 防篡改）；会话日志 `dsh_sessions` 卷留存 90 天/1 万条滚动清理 |

健康检查：app 用 `/api/health`；dsh-engine 无 /health，用 FastAPI 自动生成的 `/openapi.json` 探活。国内构建走腾讯 pip 镜像与 npmmirror（litellm 版本须取镜像快照存在的档位）。

生产环境：腾讯云 Docker Compose 单机部署（SQLite 挂卷；SMTP/westock/LLM key 生产配置项，见《生产回滚runbook》）。

## 9. 质量保障

- **TDD 流程**：RED → GREEN → REFACTOR；提交前 `pytest tests/ -v` 全绿 + verification-before-completion。
- **测试规模**：580 例（57 个测试文件），按 test_agents / test_api / test_data / test_llm / test_memory / test_models / test_services / test_migrations / test_upgrade_dual_track / test_vendor 分域组织。
- **可测性设计**：DshRunner / CalcClient 均为 Protocol 抽象，测试注入 Fake；时间相关逻辑显式传参。
- **纯函数优先**：margin_engine / portfolio_calc / invest-calc 零副作用，公式可独立验证；TS 侧 vitest 冒烟测试。
- **Mock 优先开发**：LLM → MockLLMProvider、数据 → MockProvider、DSH → 规则链、Redis → 跳过；离线全栈可运行，生产一键切真实源。

## 10. 关键工程决策记录

| 决策 | 背景 / 理由 |
|:--|:---|
| LLM 分析强依赖 DSH，关 DSH 即纯规则 | 避免 LLM 直调的散装 prompt 链；DSH Harness 提供工具契约、会话管理与遥测 |
| 确定性计算 TS 为主 Python 兜底 | 计算逻辑与分析 skill 同仓同语言演进（TS 插件生态），Python 保可用性 |
| A/B 表分离 | 事实数据（行情/财报）跨用户共享一份，衍生分析按用户隔离，省采集与存储 |
| watchlist/sell 双组字段共存 | 自选与持仓分析结果互不覆盖，一次分析模式切换不破坏另一模式展示 |
| session_id 唯一化 | 根治 harness 空会话恢复导致的五段提取失败（生产事故根因修复） |
| 财报 mock 诚实原则 | 配真实源后禁用 mock 财报，宁缺勿假（数据是投资决策的底线） |
| 日记去内置 AI 分析，改聊天 @ 引用 | 单一 AI 出口：所有分析经聊天 Agent，persona 与工具统一治理 |
| nginx 变量 upstream + resolver | 容器重建 IP 漂移导致 502 的运维坑修复 |
| pnpm 固定 10.22.0 | 新版 pnpm minimumReleaseAge 策略致 frozen-lockfile 构建非确定性失败 |
| litellm 锁腾讯镜像存在的版本档位 | 国内镜像快照缺档致生产构建失败的适配 |
